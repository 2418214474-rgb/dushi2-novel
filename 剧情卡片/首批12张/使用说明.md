# 完整故事卡与聊天抽卡

本批材料统一保存在 `C:\Users\YWJ\Downloads\拆书2\拆解\都市` 下。剧情卡片、抽取记录、简要剧情及未采纳梗概放在 `剧情卡片\首批12张`；新书设定与既定剧情放在 `新书\城中村医武逆袭`。今后基于这些都市素材生成的写作材料也沿用这一存放位置。

打开“卡片册.md”即可阅读12张卡。“编号目录.json”记录固定编号、卡册位置、原始拆解文件、章节、事件和校验值；“卡片库.json”保存可编辑内容。来源是现有剧情流程拆解，未宣称逐字复核了完整小说原文。

在聊天里可以直接说：

- “展开A003”：查看完整经过与使用条件。
- “抽三张，目标是饭馆经营压力”：先检查前情适用性，再随机抽候选。
- “保留B002，其他重抽”：保留一张并重新抽取其余；旧候选可能再次抽中。
- “主卡B002，借A002的举证转折”：先给一段简要剧情，其他卡只提供需要的局部结构。
- “这个方向可以，展开梗概”：确认简要剧情后，再生成详细剧情梗概。
- “采纳这版梗概”：明确采纳后才形成下一轮前情；选主卡本身不算采纳。

抽卡目标变化或采纳新梗概后，须重新审查“试抽配置.json”的上下文与合格池。当前配置专用于前两章方案之后的饭馆经营压力。设定文件发生变化时，工具会要求复核，不会默默沿用旧池。

流程为：抽取候选→选择主卡→简要剧情→用户确认方向→详细剧情梗概→用户明确采纳。简要剧情通常约100—200字，说明谁遇到什么麻烦、如何应对、有什么转折及结果，先让作者判断故事是否想写。

“抽取记录.json”保存抽取历史、主卡选择、简要剧情确认和详细梗概采纳。每轮有随机种子与前情快照；用户选主卡后先记录选择并提供简要剧情，确认方向后才展开梗概，明确采纳梗概后才更新前情。选卡、确认方向与采纳是三个不同步骤。生成失败、放弃或要求改稿均不算采纳。

计划试用两至三轮。每轮记录：是否更容易选方向、实质改稿次数、前情衔接是否通过。选择与反馈需在聊天中实际发生，不能用脚本模拟成已经完成的试用。

## 本地读取与抽取

以下命令在本目录运行，无需API或网站：

```powershell
node .\卡片工具.mjs show A003
node .\卡片工具.mjs verify
node .\卡片工具.mjs draw
node .\卡片工具.mjs draw B002
```

最后一条仅在B002是上一轮候选且当前仍适用时有效。每次draw都会新增真实抽取记录；只想查看时用show，避免误增加轮次。工具不会选定主卡或自动采纳。

编辑卡片库后运行“node .\卡片工具.mjs build”，即可更新卡册和编号目录。工具仅向本目录写入生成文件，来源拆解、网站数据与既定前情只读。

换聊天时，提供本目录路径和编号目录；如果新聊天不能访问当前磁盘，需要附上卡册或具体卡片，以及试抽配置和已采纳梗概。单独一个编号不能跨设备自动带出卡片内容。
