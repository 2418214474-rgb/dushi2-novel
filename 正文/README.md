# 正文发稿规则

执行入口：项目根目录的 [写作审核工作流.md](../写作审核工作流.md)。

原稿命名：`第XXX章_章节名.md`；审核修改版命名：`第XXX章_章节名《修改版》.md`。

每次生成前读取：

1. `新书设定.md`
2. `新书前30章功能大纲.md`
3. `对标书行文蒸馏.md`
4. `AI味禁用清单.md`
5. `前情台账.md`
6. 最近三章最新修改版，没有修改版时读取原稿
7. `审核档案.md`与`章节进度.md`

收到“生成下一章”后，先在聊天提供约150—250字剧情概括，等待作者确认。收到“确认，写正文”后，按确认概括生成约2100—2300字正文，再重新读取完整正文进行审核。

保存原稿并复制为修改版，在问题旁插入《修改意见：具体问题及建议》。修改版保留原文，不直接替作者改写。同一章只保留当前原稿和对应修改版；新一组文件完整生成后清理上一组。笔误只在聊天单独告知。

生成后章节状态为“正文已生成，待作者修改”。作者确认修改版后才更新正式前情台账。直接要求下一章时承接最新修改版，并在概括中说明影响续写的未解决问题。

内部检查项目：前情连续、人物认知、关系阶段、能力边界、实际收益、冲突升级、AI禁用词、重复动作、原创措辞与章末钩子。

正文与审核完成后的聊天交付只包含：原稿链接、修改版链接、字数、简短审核结果及发现的笔误。
